# P0 foundation verification

Date: 2026-10-26. User approval started implementation; it did not waive acceptance gates.

## Delivered scope

Local Node/Fastify service; React workspace; SQLite app metadata and libfx local journals; paired browser authentication; credential vault; project selection and read-only file access; compatible-provider/Gateway configuration; experimental ChatGPT auth/protocol bridge; bounded Vercel synthetic proof UI. The UI uses the original logo bytes and approved theme direction.

This is a foundation checkpoint. P0 remains open and P1 is not complete.

## Local evidence

Environment: macOS arm64, Node **24.22.1**, libfx **0.0.14 / API 3**, native backend available, better-sqlite3 **13.0.3** (SQLite **3.53.4**). Dependency versions and integrity are pinned in `package-lock.json`.

`npm run check` runs TypeScript, thirteen contract/integration tests, and the production build. Tests use synthetic local fixtures and injected credentials, never a real account. The suite covers:

| Check | Evidence / boundary |
| --- | --- |
| Native text/function round trip | libfx dispatches a real read-only host tool against a local HTTP model fixture. |
| Persistence and deduplication | Same message ID produces no second model request; a reopened agent restores history. |
| Viewer detach / cancel | Canceling a viewer preserves the turn; explicit session cancellation ends it and a subsequent prompt succeeds. |
| Browser API | Pair-once, strict Host/Origin, HttpOnly/SameSite cookie, authenticated metadata, private-data-root rejection, durable chat, and concurrent-turn rejection. |
| Vault | Authenticated encryption, record-ID binding, deletion, and no plaintext secrets in API metadata. Production Keychain interaction is not live-verified. |
| Credential persistence | Synthetic compatible-provider key absent from all durable session files. Gateway's distinct wire protocol/live path remains unverified. |
| Files | Rejects traversal, absolute paths, sensitive directories, leaf/ancestor symlinks, oversized files, and binary input. This is scoped read access, not an OS sandbox. |

`npm audit --audit-level=high`: zero reported vulnerabilities at this checkpoint. The scoped Zod override addresses the vulnerable version pinned by `@vercel/cli-config`. An audit does not establish runtime security or live SDK compatibility.

Browser verification uses the built app at desktop 1440×1000 and mobile 390×844: pairing, project creation, synthetic prompt → `list_dir` → streamed answer, saved chat reopening after page reload, activity/file inspector, and layout overflow checks. The synthetic model is visibly labeled **LOCAL TEST FIXTURE**. No console errors/warnings were observed for that flow. Full accessibility, keyboard, recovery and performance acceptance remain P3 work.

Initial measured install footprint on this Mac: approximately 240 MiB in `node_modules` (including development tools and packaged native/WASM variants), approximately 492 KiB in `dist` before the final formatting/doc pass; production client JavaScript around 255.6 KiB / 79.6 KiB gzip. These are observations, not cross-platform budgets or a packaged-app size.

## libfx cancellation fix

Canceling `session.stream()` while its asynchronous reader is opening can leave a polling timer alive in the pinned upstream source. The API test exposed this as a completed test process that never exited. `scripts/patch-libfx.cjs` adds a cancellation flag and cancels a reader that finishes opening after detachment.

- Upstream `durable.js` SHA-256: `a5ac4a2ceb41284ca3e364c974daacac5ddba9c8b5bb07d9c1ca90f5a8901dec`.
- Patched SHA-256: `aa1c04105b0d698fdbdf162dab218c8d7f5b25a73ea057ffee493cfda89491af`.
- Installation accepts exactly these two forms; changed upstream source requires a review. No dependency source or binaries are vendored.

## Open gates and next work

1. **Reasoning state:** retain provider-required encrypted reasoning items through tool calls, restart, branch/context compaction and cancellation without mixing chats/accounts. Until a supported integration is proven, reject these responses. The current bridge is not general ChatGPT compatibility.
2. **Effect reconciliation:** persist operation intent/outcome and prohibit new effectful calls while an earlier outcome is unknown. A model-facing error and `idempotent:false` alone are insufficient. The application exposes no effectful agent tools yet. An unknown sandbox proof disables automatic reruns; provider reconciliation UI/API is still to implement.
3. **Live accounts:** user-entered account authentication, text/tool round trips, model catalog, refresh, revocation, quota errors and restart acceptance. Gateway and local model installations also need their own receipts. No account files from other applications were reused.
4. **Real sandbox:** use the explicit acknowledged synthetic check, then verify creation, artifact bytes, stop status, expiry and provider resource cleanup. The SDK is pinned to 3.9.0. A non-stopped response or failure stays `unknown`; never report cleanup from a requested stop alone.
5. **Distribution / alpha work:** verify clean installs on advertised platforms, then finish P1 approvals, writable artifacts, policy/budgets, configured/effective presets, migrations and recovery UX. Memory, Plugin Hub and additional adapters follow the approved stages.

The original preliminary spec and reference Agent Zero checkout remain unchanged. CI results are authoritative in the linked repository's workflow runs; local evidence is not a claim that hosted CI has passed.
