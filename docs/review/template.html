The proposed build

Small core. Real choices.

Keep the agent loop focused. Make the things around it replaceable.

01 / MODELS

Bring the access you already have

Gateway, direct APIs, local inference, and a dedicated ChatGPT subscription connection. Clear capabilities and billing routes.

02 / EXECUTION

Choose where the work runs

Vercel and E2B adapters establish the contract. Add compatible services from Settings. Direct host execution is an explicit choice.

03 / MEMORY

Keep useful knowledge close

Inspectable local memory, optional Hugging Face model downloads, and independent embedding settings. No mandatory vector service.

04 / EXTENSIONS

A useful, honest Plugin Hub

Browse the actual ecosystem with clear compatibility labels. Skills, MCP, Slim extensions, and an optional Agent Zero bridge.

05 / CONTINUITY

Pick up where you left off

Durable messages, cursor replay, explicit Stop, and receipts for side effects. Recovery shows what is known and what needs checking.

06 / EXPRESSION

Minimal can still feel personal

Original Agent Zero symbols, Graphite and Paper, carefully chosen accents, density, text scale and an optional inspector.

Resolve first: libfx 0.0.14 uses a different ChatGPT login path from OpenAI's documented local OSS flow. The first engineering milestone proves the public Responses integration before subscription access is called ready.

Build in four verifiable stages

P0

Prove the foundation

Runtime restart, ChatGPT integration, sandbox lifecycle and packaging.

P1

Make it useful

The workspace, providers, files, one sandbox, approvals and recovery.

P2

Make it extensible

Memory, local embeddings, delegation, Hub, MCP and a second sandbox.

P3

Make it release-ready

Accessibility, migration, recovery drills, docs and measured performance.
